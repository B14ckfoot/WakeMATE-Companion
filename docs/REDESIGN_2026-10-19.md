## Implemented behavior

- Version 0.3.0, protocol 5; QR contract v3 and /v1 route names retained.
- The phone requires the scanned certificate pin for authenticated traffic.
  Missing/corrupt pins and secure-storage failures do not enable HTTP. A new
  address retains the original pinned identity; pin mismatches are rejected.
- Companion HTTP compatibility, when explicitly enabled, exposes only public
  credential-free health. It cannot enroll, authorize, or execute commands.
- Permanent shared bearer credentials, keyring/file fallback, and global
  input/power flags are retired. Old OS credential entries remain inert.
- Device token hashes and selected grants share a versioned atomic registry
  snapshot. Legacy records retain identity with status/wake-only permissions.
  Storage errors suspend access and require explicit recovery.
- Desktop presets cover status/wake, media, desktop input, and desktop plus
  power. Keyboard access is explicitly broad trust in the signed-in account.
- Pairing has deadlines and prompt identity. Pause, permission/revocation
  changes, reset, and restart invalidate pending authority. A late callback
  cannot approve a newer enrollment. Status polling is scoped to its device
  or consumed invitation's own enrollment.
- One bounded input thread uses checked Windows input calls, validated commands,
  short text batches, live authorization, cancellation, and owned held state.
  Queue capacity is 32; text is limited to 1024 Unicode characters. Held mouse
  buttons expire after two seconds without successful owner input.
- The phone renews a held drag every 500 ms, serializes down/up ordering, and
  releases on route/device/lifecycle/offline/error changes. Desktop expiry
  remains the fallback when the phone cannot communicate.
- HTTP requests have bounded concurrency/deadlines, successful commands have
  per-phone budgets, and system actions are serialized.
- Native settings and permission dialogs provide local/private-LAN consent,
  adapter selection, pause/resume, permissions, and reset recovery. Pairing QR
  rendering waits for real HTTPS readiness. Listener lifetime is separated
  from tray rendering in server_thread.rs.
- Runtime rejects elevated or service-session execution and keeps a single
  machine owner. Setup does not launch the tray. Typed Windows sleep/lock
  requests preserve platform security boundaries and report accepted/failure
  results instead of assuming shell-command dispatch completed the action.
- Installer firewall rules use Private profile, LocalSubnet, TCP 7778 and UDP
  41234. Upgrades request graceful exit for the exact installed path, never a
  global basename kill. Startup cleanup matches the installed path in loaded
  user hives; offline profiles still need real multi-user QA.
- Discovery is rate-limited and uses cached private interface/subnet selection.
  Unauthenticated replies omit MAC addresses. Discovery bind errors are visible.
- README, repository rules, migration, security, troubleshooting, release, and
  platform notes now describe the actual Windows-first behavior.

## Remaining release validation

- Run the native UI and installer in a clean Windows VM: standard user,
  over-the-shoulder UAC, already-elevated launch refusal, upgrade, uninstall,
  startup cleanup, multiple sessions, and Private/Public network transitions.
- Test physical Android and iOS QR scanning, pin rejection, changed addresses,
  least-privilege grants, pause/revocation during input, lost button-up,
  foreground/background drag behavior, and real firmware/NIC sleep/wake.
- No new APK/iOS binary was built or installed. Mobile source and JS/native
  project invariants were checked; Expo Go alone cannot validate pinned TLS.
- macOS is an unvalidated headless developer preview for this revision, with
  no interactive onboarding/approval/input parity. Its CI configuration is not
  a verified macOS build or mounted-package test.
- Both Windows executable and installer are unsigned. Real signing and release
  review remain required before public distribution.
- Same-user/admin compromise and OS/driver behavior remain outside the network
  authentication guarantee. A failed storage operation is not durable revocation
  until recovery succeeds; retain the surfaced error and pause state.

No installed app, credentials, firewall, or startup configuration was changed.
No live mouse/keyboard/power/Wake-on-LAN action was run. Unit input uses a fake
backend; the exit-event test is scoped to its test executable. No commit, push,
tag, release, or deployment was performed.
