## Failure scenarios and implementation plan

1. **Revoke, disk full, restart:** silently ignoring persistence resurrects
   a supposedly revoked token. Make mutations return errors, flush atomic
   writes, and do not publish successful registration before persistence.
   Failed revocations remain denied in memory and must show an actionable error.
2. **Open prompt, reset/restart, click Yes:** stale callbacks must never grant
   fresh authority. Serialize prompt completion/invalidation, invalidate the
   QR session, and reject expired/cancelled callbacks before any writes.
3. **Upgrade after disabling discovery/startup:** preserve explicit choices;
   apply convenient LAN defaults only to a genuinely new installation.
   Corruption is not permission to widen exposure.
4. **Malformed shortcut / extreme scroll:** validate the whole command before
   the first OS event and bound arithmetic before calling the input backend.
5. **Browser, token leak, many source IPs:** reject browser origins, mark
   API replies no-store, bound lockout memory, and use TLS by default for new
   configs while retaining explicit old compatibility settings.
6. **Release builds green despite advisories:** run the actual advisory scan,
   address applicable findings, enforce the gate, and run the Windows
   format/lint/test/build pipeline. Keep protocol schema/version unchanged.

Implement focused fixes for these scenarios, followed by regression tests
that never send real desktop input or power commands. Record remaining
platform, packaging, and live-phone limitations explicitly.

## Remaining risks and release work

1. **Legacy access:** explicit old HTTP settings and the permanent shared
   bearer-token control path remain for compatibility. Retire them with a
   coordinated mobile migration. Fresh QR pairings use scoped sessions and
   per-device tokens. A per-device revocation does not revoke a separate
   legacy shared credential; rotation revokes both paths.
2. **Resource and network behavior:** discovery remains unthrottled, and
   VPN/multiple-interface selection needs real LAN testing. Authenticated
   command rates and concurrent input sequences are not serialized; a held
   mouse button may need local release after a phone disconnects.
3. **Filesystem limits:** config and registry are separate files, not one
   crash-atomic transaction. Approval failures attempt config rollback and
   never authorize the new device on registry failure. If a revocation
   cannot persist, its old disk record may return after restart; the desktop
   now reports this instead of claiming success. Same-user/admin tampering
   and Windows directory ACLs remain part of the local trust boundary.
4. **Real-device QA remains:** installer/UAC/upgrade/uninstall in a clean VM,
   physical Android/iOS QR pairing and TLS pin rejection, actual sleep/wake,
   input gestures, network changes, and UI appearance. No installed app,
   real credentials, startup registration, or firewall settings were changed
   or exercised during this audit. The new binary has not been installed.
5. **Distribution:** binaries remain unsigned; signing, final notices/license,
   and macOS UI/packaging parity remain release work. macOS was reviewed in
   source and dependency resolution only; no macOS build ran on this host.

All changes are local and uncommitted. No push, tag, release, or deployment
was performed. This is a source audit with automated regression validation,
not a penetration-test certification or a claim that live-device QA passed.
